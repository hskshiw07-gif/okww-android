# ok-ww Android

一个用于自动化完成《鸣潮》部分任务的 Android 辅助应用。它通过 Android 屏幕捕获、设备端文字与图像识别，以及 Android 无障碍服务与界面交互；不会读取或修改游戏文件。

本项目仍在开发中，不代表稳定版本。当前支持的流程和角色战斗方案有限；单元测试通过也不代表已在所有设备上完成端到端验证。本仓库不包含 APK。

## 构建

- JDK 17
- Android SDK Platform 35
- Gradle 8.11.1

可将本目录导入 Android Studio。也可以安装 JDK、SDK 和 Gradle，并使用项目本地 `.android-tools/` 目录布局，然后运行：

```powershell
.\build.ps1
.\build.ps1 -TestOnly
```

构建脚本会将生成文件和 APK 写入本地构建/输出目录；这些目录已加入忽略规则。使用 `-Fixtures` 时还会打包 Android 仪器测试 APK。

## 每日测试

在「设置 → 开发设置」开启「测试环境」，然后运行「每日 · 无音区」。测试模式忽略活跃度，余额足够时每次只领 60 普通波片，计入原账本（每账号每游戏日最多 240），副本结束后检查免费奖励。开测时的普通波片不足 60 则只跑战斗和领奖预览，取消并退出，不实际领取，也不标记每日完成。不补充、不兑换、不购买。切换开关会停止当前任务，需要重新启动；多账号每日暂不支持测试模式。

本轮战斗中确认角色倒地后，会取消复苏道具界面并退出副本。若全队尚未恢复，则识别地图中的中枢信标，核验名称后免费传送；连续两帧确认同账号、角色身份及全队满血后，重新核验编队再进场。恢复保留原波片账本，每轮最多两次，不使用复苏道具。2400×1080 恢复页会单独放大血量和延迟小字，避免把血量分隔符误读后一直等待。

## 刷 4C 声骸（离线试验版）

### 战斗节奏离线修正

心的二段重击完成后，按有效战斗时间最多等待约 3 秒尝试大招（墙钟兜底 6 秒，避免动画冻结提前截断），再经身份核验交给队伍调度，不再耗尽整段终结窗口。绯雪只在检测到长动作标记时要求回路阶段；爱弥斯长动作标记暂时丢失时停止普攻并重新观察最多约 2 秒，仍未知则保留现场并停止。查询队伍 HUD 会复用仍在原有新鲜度范围内的观察，过期后重新截图。这些修改尚待真机验证，不代表所有识别报错已解决。

在任务中心选「刷4C声骸」，填写首领血条上的完整名称，切换到自动模式。到首领附近、未开战时，从浮窗点「开跑」。应用先核验同账号和当前编队，再在看到该首领的名称与血条后执行内置输出轴。战斗输入结束后只点近身的「吸收」，不会点「领取奖励」或消耗波片；交互消失后原地等同一目标重现，最多等 90 秒。「交互已消失」不等同于确认声骸入包。

仅按 2400×1080 布局做离线适配，首领血条与吸收交互尚未真机标定。掉落超出交互范围、首领不在原地重现或遇到无法识别的状态时，停止并保留截图。暂不支持自动传送、跑图、寻找远处掉落或重开副本。浮窗隐藏时可从采集通知停止。

## 隐私与权限

### 自动化额外负载

采集仅在请求新画面时转换全屏位图，仍保留每 200 毫秒最多一次的转换上限与原有画面新鲜度检查。无识别请求时不再持续转换位图；MediaProjection 和虚拟显示仍然运行，并非关闭录屏。战斗观察的状态文件由每帧两次写入合并为一次。OCR、头像匹配和游戏本身仍会消耗资源，实际温度改善尚待同条件真机对比；不宣称已经解决长时间挂机发热。

- 屏幕捕获和识别均在设备本地运行；应用不会上传游戏画面或账号标识。
- 账号计划和运行记录保存在应用私有存储中；仓库不附带个人账号 ID 或手机号作为默认值。
- 开发环境中的账号专属默认配置已移除。单账号每日任务默认选择列表中的第一项「无音区」；如需选择其他项目，请在多账号任务中配置账号计划。
- 应用申请 MediaProjection（屏幕捕获）和无障碍权限，是因为屏幕读取与界面操作需要这些权限。只有用户主动启动后，任务才会运行。
- 用户主动请求时，应用会从 `RedeemFeed.java` 中声明的地址获取可选的公开兑换码信息。本代码中没有分析或遥测服务地址。
